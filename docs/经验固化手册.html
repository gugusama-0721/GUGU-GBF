🔥 GUGU-GBF 数据读取经验固化手册

碧蓝幻想辅助 · 从「注入脚本 hook 失败」到「debugger 稳定读取真实数据」的完整排障记录 · 参考 Tarou 机制

📌 一句话结论

读取 GBF 配置数据（角色/武器/召唤/队伍）的可靠方案是 chrome.debugger + CDP 协议直接读 HTTP 响应体，而不是往页面注入脚本 hook。GBF 的 Content-Security-Policy 会阻止扩展脚本注入主世界，导致所有 hook fetch/XHR/jQuery 的方案全部失效。

debugger.attach→ Network.enable→ responseReceived 匹配 URL→ getResponseBody 读 JSON→ storage 缓存 → 侧边栏显示

尝试方案结果原因

MAIN world 注入 hook.js失败GBF 的 CSP script-src 'self' 阻止扩展脚本注入

💡 核心认知：GBF 的 CSP 为何挡得住脚本注入却挡不住 debugger？—— CSP 约束的是「页面内加载的脚本」，而 chrome.debugger 是浏览器层的调试协议，走独立通道。

🧠 关键洞察：Tarou 的「配置辅助」其实全部基于「一场战斗的 WebSocket 实时事件」，它不读你的角色/武器/召唤图鉴列表。这部分配置数据要靠 HTTP 主动查询（正是我们用 debugger 读通的）。所以两者是互补、非替代。

// debugger 附加 + Network.enable，复用 Tarou 思路但不只靠 WS，还读 HTTP body
async function attachDebug(tabId){
  await chrome.debugger.attach({tabId},"1.3");
  await chrome.debugger.sendCommand({tabId},"Network.enable",{
    maxTotalBufferSize:10_000_000, // 大 JSON 响应完整
    maxResourceBufferSize:10_000_000});
}
// onEvent → 匹配接口 → getResponseBody → tryParseJson

🚧 避坑清单（血的教训）

方案层面

  • ❌ 别用 content script hook fetch/XMLHttpRequest —— 隔离世界对象，拦不到主世界请求
  • ❌ 别指望往页面注入脚本 —— GBF CSP 挡死，诊断「inject未加载」即此
  • ✅ 用 chrome.debugger —— 浏览器协议层，最可靠

实现层面

  • ⚠️ debugger attach 会弹「正在调试此浏览器」提示条（正常现象）
  • ⚠️ 同一标签页同时只能一个扩展 attach，与 Tarou 冲突会失败 → 测试时需先停用 Tarou
  • ⚠️ 响应体可能带 padding/前缀 → 用 tryParseJson 智能截取 {... 到末尾 }
  • 💡 加诊断面板（attach状态/捕获数/最近URL），排查高效——别黑盒猜
